  Работа содержит серьёзную инженерную базу и ряд ценных идей, но имеет критическое расхождение между предложенным планом и реальной реализацией, а также фундаментальные методологические проблемы. Ниже — детальный разбор.

  ---
  I. КРИТИЧЕСКИЙ РАЗРЫВ: ПЛАН vs. РЕАЛЬНОСТЬ

  Это самая серьёзная проблема, которую рецензент обнаружит за 10 минут.

  Что описано в плане

  8 экспериментов с сеткой весов: selective_A (w1=+1, w2=−1), single_A (+1, 0), biased_A (+1, +0.3), balanced_AB (+1, +0.7), dual_linear (+1, +1), dual_min, single_B, selective_B. 3 seeds на каждый. Заявленная новизна — «карта всего пространства
  возможностей».

  Что реализовано в коде

  experiment.yaml содержит 3 режима: single_a, single_b, double (worst-case max(z_A, z_B)). 5 seeds на каждый. Альтернативные скаляризации (harmonic, geometric, weighted_sum, weighted_product, tchebycheff) вычисляются оффлайн из уже
  сгенерированных молекул, а не используются как RL-reward при генерации.

  Почему это критично

  1. Оффлайн пересчёт ≠ оптимизация. Применение формулы harmonic_mean(d_A, d_B) к молекулам, сгенерированным под reward=max(z_A, z_B), это post-hoc ранжирование, а не генерация с другим reward. Молекулярное распределение определяется
  reward-функцией при обучении. Два генератора с reward=sum(z_A, z_B) и reward=max(z_A, z_B) дадут принципиально разные молекулы, потому что RL-агент выучивает разные стратегии сборки.
  2. «Карта пространства весов» не существует. Имеются 3 точки (single_a, single_b, double), а не 8. Это сравнение «single vs dual», стандартный дизайн, а не систематическое сканирование weight-space.
  3. Клейм о фазовых переходах невозможен. Для обнаружения фазового перехода при w2=X нужна плотная сетка по w2 с реальной RL-оптимизацией в каждой точке. С 3 точками нет данных для кривых «зависимость метрик от w2».

  Вердикт: Либо реализовать 8 режимов с разными reward-функциями (что требует 8×5×9 = 360 RL-запусков вместо текущих 3×5×9 = 135), либо честно переформулировать research question как «single vs dual comparison», без клейма о weight-space
  exploration.

  II. СИЛЬНЫЕ СТОРОНЫ (что хорошо и почему)

  1. Инженерное качество — ОТЛИЧНО

  - 396 тестов, ~80% покрытие, включая интеграционные тесты для всех стадий пайплайна
  - Ruff + ty чистые — zero warnings
  - Атомарный cache I/O (fcntl.flock + temp+rename) — правильное решение для параллельных запусков
  - Docker-контейнеризация FREED++ с monkey-patching для dual-target — элегантное решение без форка апстрима
  - Dual backend Boltz-2 (NIM REST API + CLI subprocess) с cache separation по context hash
  - Run manifests для provenance tracking — воспроизводимость на уровне MLOps

  Почему это сильно: В computational drug design большинство работ — «скрипт на коленке». Здесь промышленное качество, что резко повышает доверие к результатам.

  2. Ортогональная оценка (UniDock → Boltz-2) — ХОРОШО

  Использование другого метода для оценки (Boltz-2, transformer) vs. обучение (UniDock/Vina, physics-based) разрывает circular evaluation loop. Это реальный методологический вклад.

  Подтверждение из литературы: SynFlowNet + Boltz-2 (Cretu et al., ICLR 2025; Passaro et al., bioRxiv 2025) — прецедент, но там Boltz-2 используется КАК reward, а не как ортогональный оценщик. DualDocking — первый случай Boltz-2 как пост-скоринга
  для RL-генерированных молекул.

  3. Пре-регистрация — ОТЛИЧНО

  docs/preregistration.md и docs/statistical_analysis_plan.md с зафиксированными порогами, критериями успеха (≥3/5 core pairs, Cliff's delta > 0.33), чувствительностями (T ∈ {-1, 0, +1}). Это редкость в computational chemistry и резко повышает
  доверие. Журнал ценит это.

  4. Known limitations — ХОРОШО

  docs/novelty_report.md (строки 271–283) содержит таблицу «Objection → Counter-Argument» с 8 ожидаемыми возражениями рецензентов. Упоминание Bret et al. (2026, JCIM) о нечувствительности Boltz-2 к мутациям — честное и важное.

  5. Калибровка z-score — ПРАВИЛЬНО

  Нормализация скоров через 1000 ZINC-декоев для каждой мишени решает проблему несопоставимости шкал. Redocking-валидация + enrichment benchmarking (AUROC, BEDROC) — стандартный QC.

  6. Robustness engineering — ОТЛИЧНО

  - Z-score clamping (±10) предотвращает доминирование corrupt scores в RL-градиенте
  - Score validation [-20, 10] + CPU fallback для коррупционных GPU-batch
  - SMILES neutralization для Boltz-2 (charged species crash fix)
  - Individual retry + partial result parsing при timeout

  III. СЛАБЫЕ СТОРОНЫ (что плохо и почему)

  1. СТАТИСТИЧЕСКАЯ МОЩНОСТЬ — КРИТИЧЕСКАЯ ПРОБЛЕМА

  Проблема: 5 seeds — единица статистического вывода. ~1000 молекул на seed создают иллюзию большой выборки.

  Литературная база:
  - Cameron, Gelbach, Miller (2008, Rev. Econ. Stat. 90(3):414–427): bootstrap с 5 кластерами over-rejects. Реальный coverage 95% CI — около 85–88% вместо заявленных 95%.
  - Colas, Sigaud, Oudeyer (2018, arXiv:1806.08295): для обнаружения medium effect (Cohen's d=0.5) в deep RL при 80% power нужно n≥34 seeds. С n=5 можно обнаружить только d≥1.33 — это гигантский эффект.
  - Henderson et al. (2018, AAAI): seed-to-seed variance в deep RL достаточна для инверсии ранжирования алгоритмов.

  Конкретные числа для DualDock:
  - Иерархический bootstrap с m=5 seeds: 5^5 = 3125 уникальных Level-1 паттернов. Лучше, чем m=3 (27 паттернов), но всё равно marginal.
  - Cliff's delta при n=5 vs n=5: только 26 возможных значений (мультипли 1/25). Порог |δ|≥0.33 никогда не достижим точно — ближайшие: 0.28 или 0.36.
  - Two-sample t-test при n=5 vs n=5, α=0.05, 80% power: минимальный Cohen's d = 1.33.

  Рекомендация: Либо увеличить seeds до ≥10 (trade-off: 500 молекул × 10 seeds > 1000 × 5 seeds для between-condition inference), либо отказаться от формальных p-value и CI и перейти на:
  - rliable framework (Agarwal et al., NeurIPS 2021, Outstanding Paper Award): performance profiles, interquartile mean, probability of improvement
  - Wild cluster bootstrap (Canay, Santos, Shaikh 2021) вместо стандартного percentile bootstrap
  - Mixed-effects models: hit_both ~ mode + (1|pair) + (1|seed:pair) — один тест вместо 10 pairwise, заимствует силу через pairs

  2. BOLTZ-2 КАК «ГЛАВНЫЙ СУДЬЯ» — ПРОБЛЕМНЫЙ КЛЕЙМ

  Проблема: План называет Boltz-2 «самой точной на сегодня моделью предсказания связывания» и «главным этапом». Это overclaim.

  Фактические данные:
  - Boltz-2: Pearson r=0.66 на 4-target FEP+ бенчмарке (CDK2, TYK2, JNK1, p38). Это intra-series корреляция (congeneric pairs).
  - PL-REX (независимая оценка): Pearson ~0.42 — значительно хуже.
  - DeepMirror: per-target r = 0.26–0.81 — высокая вариабельность.
  - Bret et al. (2026, J. Chem. Inf. Model. 66(3):1511–1521): Boltz-2 «insensitive to key binding site mutations» — affinity predictions не различают wild-type vs. мутант.
  - Для сравнения: ML scoring functions на CASF-2016 (supervised, не co-folding) достигают r=0.82–0.86 (EIGN, GraphWater-Net, AK-Score).

  Почему это проблема:
  - Boltz-2 обучен на ~750K пар из ChEMBL/BindingDB/PDBbind. Ваши мишени (CDK2, ERK2, AChE, BACE1, GSK3B) — топовые ChEMBL-мишени с тысячами записей. In-domain bias неизбежен.
  - Correlation r=0.42–0.66 означает, что R²=0.18–0.44 дисперсии объясняется моделью. >50% — шум.
  - Нечувствительность к мутациям ставит под вопрос, «видит» ли Boltz-2 реальное связывание или выучил structural bias.

  Рекомендация:
  - Не называть Boltz-2 «главным судьёй» — это один из суррогатов, не ground truth
  - Честно обсудить R² ≈ 0.18–0.44 и Bret et al. как ключевое ограничение
  - Добавить оговорку: все выводы — relative ranking between strategies, не предсказание абсолютной аффинности
  - Идеально: добавить FEP+ валидацию хотя бы для топ-5 молекул из каждого режима (если доступен софт). Или: перекрёстная валидация через GNINA (CNN-based, принципиально другой подход).

  3. ОТСУТСТВИЕ GNINA, GROMACS, ФИЛЬТРОВ

  Проблема: План описывает 3 метода оценки (Boltz-2 + UniDock + GNINA), MD-симуляцию для топов, и фильтрацию (Lipinski, QED, PAINS, SA). В коде реализован только Boltz-2 + UniDock (как RL reward).

  Почему это проблема для статьи:
  - Без GNINA нет «трёх независимых судей» — только два (и один из них = RL-reward, не полностью независимый)
  - Без MD нет валидации стабильности — «скор врал, молекула уплыла» невозможно проверить
  - Без фильтров нет drug-likeness — «генерирует молекулы, а не лекарства» (стандартное возражение рецензента)

  Рекомендация:
  - GNINA: минимальная интеграция — gnina --score_only на уже сгенерированных позах Boltz-2. Часы работы, не дни.
  - Фильтры: RDKit-скрипт в 50 строк (Lipinski, QED, PAINS, SA). Применить post-hoc, не как constraint.
  - MD: не обязательно для первой статьи, но нужно явно указать как limitation + future work.

  4. NOVELTY CLAIM «SELECTIVITY + DUAL-TARGET НА ОДНОЙ ШКАЛЕ»

  Проблема: Заявлено как «unique conceptual contribution», но в реализации нет selective mode (w2 < 0). Только single_a (w2=0), single_b (w1=0), double (обе мишени).

  Литература, усложняющая клейм:
  - Horwood & Noutahi (REACTOR, ACS Omega 2020): RL molecular design с selectivity (DRD2 vs D1/D3). Не weight-space, но selectivity через multi-objective RL.
  - Isigkeit et al. (Nature Comms 2024): dual-target ligand design через CLM fine-tuning. Не structure-based, но dual-target generation.
  - Lembo & Bottegoni (2024): DTDL retrospective analysis — selectivity as a spectrum.
  - REINVENT 4 (Loeffler et al., J. Cheminformatics 2024): multi-objective scoring с configurable weights. Нет systematic grid, но механизм есть.

  Вердикт: Клейм «selectivity + dual-target in one study» необоснован в текущей реализации (нет selective mode). Если добавить w2=-1 и w2=-0.5 режимы — клейм усилится до HIGH novelty.

  5. TARGET OVERLAP В CORE SET — ОСЛАБЛЯЕТ CROSS-PAIR CONSISTENCY

  Проблема: Из 5 core pairs: AChE в 2 парах (AChE_BChE, AChE_BACE1), BACE1 в 2 парах (BACE1_GSK3B, AChE_BACE1), GSK3B в 2 парах (BACE1_GSK3B, GSK3B_CDK5). Это нарушает независимость.

  Следствие: Критерий «≥3/5 core pairs significant» — ложная строгость. Если результат зависит от характеристик AChE, 2 из 5 «побед» могут быть одним и тем же сигналом.

  Рекомендация: Добавить random-effects for target (не pair) в mixed model. Или: провести sensitivity analysis с leave-one-target-out (поочерёдно убирать AChE, BACE1, GSK3B и смотреть, сохраняется ли результат).

  6. ЕДИНСТВЕННАЯ СКАЛЯРИЗАЦИЯ В RL — ОГРАНИЧИВАЕТ ВЫВОДЫ

  Проблема: RL-reward = max(z_A, z_B) (worst-case). Это единственная функция, определяющая, какие молекулы генерируются. Все остальные (harmonic, geometric, tchebycheff) — post-hoc ранжирование тех же молекул.

  Почему это слабо: Worst-case — очень специфическая стратегия. Она заставляет генератор подтягивать худшую мишень. Молекулы, хорошие для sum(z_A, z_B) (линейная комбинация), могут быть принципиально другими — и никогда не будут сгенерированы.

  Литература: Das & Dennis (1998, SIAM J. Optim. 8(3):631–657) показали, что weighted-sum скаляризация пропускает вогнутые части Pareto-фронта. Worst-case (Tchebycheff) находит неё, но пропускает выпуклые зоны. Полная карта требует оба подхода с
  разными весами.

  Рекомендация: Минимум: добавить RL-обучение с reward = z_A + z_B (linear sum, w1=w2=1). Два режима скаляризации × 2 целевых функции = 4 категории вместо 3. Это уже позволяет сравнить «worst-case vs linear» как secondary finding.

  V. РЕКОМЕНДАЦИИ ДЛЯ MAJOR REVISION

  Минимальный путь к Q1 (наименьшие усилия):

  1. Переформулировать research question как «single vs dual comparison with orthogonal evaluation» — без weight-space exploration клейма
  2. Добавить фильтрацию (50 строк RDKit, post-hoc)
  3. Добавить power analysis в SAP
  4. Переработать статистику: mixed-effects model + descriptive per-pair + Cliff's delta as exploratory
  5. Смягчить Boltz-2 язык: «computational surrogate» вместо «main evaluation»
  6. Добавить novelty metrics: internal Tanimoto diversity, scaffold uniqueness

  Максимальный путь к Nature-tier:

  1. Реализовать 6+ RL-режимов с разными reward-функциями (w2 ∈ {-1, -0.5, 0, 0.3, 0.7, 1.0})
  2. 10+ seeds per condition (500 mol × 10 seeds)
  3. GNINA + GNINA CNN-score как третий ортогональный оценщик
  4. MD для топ-5 из каждого режима (48 симуляций × 50ns)
  5. FEP+ для топ-3 из лучшего dual vs лучшего single
  6. rliable framework для всей статистики
