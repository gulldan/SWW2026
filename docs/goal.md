# Цель проекта

## Гипотеза

RL-генерация молекул, оптимизированная под **двойную целевую функцию** (объединённый скор по мишеням A и B), порождает молекулы с более высоким **dual hit-rate**, чем single-target оптимизация с последующей кросс-оценкой.

## Нотация

В проекте используются два типа скоров с разной ролью:

| Символ | Источник | Единицы | Роль |
|--------|----------|---------|------|
| `d_A`, `d_B` | UniDock GPU (docking) | kcal/mol, lower-is-better | **RL reward** — сигнал для генерации |
| `a_A`, `a_B` | Boltz-2 (learned affinity) | log10(IC50-like, μM), lower-is-better | **Evaluation surrogate** — ортогональная оценка |

**Важно о природе `a_X`:** Boltz-2 affinity head обучена на смеси биохимических метрик (Ki, Kd, IC50, EC50 и др.), приведённых к логарифмической шкале в μM (Passaro et al. 2025). Предсказанное значение следует интерпретировать как **IC50-like surrogate**, а не как калиброванное предсказание конкретного типа эксперимента. В данном проекте `a_X` используется исключительно как **ранжирующая метрика** для сравнения стратегий генерации (single vs double); абсолютные значения не интерпретируются как экспериментальные IC50.

Два скорера **не смешиваются**: FREED++ оптимизирует только docking-скоры `d_A, d_B`;
Boltz-2 используется post-hoc для независимой оценки сгенерированных молекул.

## Метод

1. **Генератор**: FREED++ (RL-генерация молекул с UniDock GPU docking-скором `d` как наградой).
2. **Скорер**: Boltz-2 (structure-aware affinity `a`, ортогональный к docking).
3. **Сравнение**:
   - **single_a**: reward = `f(d_A)` → скоринг Boltz-2 по обеим мишеням.
   - **single_b**: reward = `f(d_B)` → скоринг Boltz-2 по обеим мишеням.
   - **double**: reward = `f(combined(d_A, d_B))` → скоринг Boltz-2 по обеим мишеням.

## Двойная целевая функция (RL reward)

Reward для FREED++ строится на **docking-скорах** `d_A, d_B` (UniDock GPU, kcal/mol, lower-is-better).

### Базовая (baseline)

`combined(d_A, d_B) = max(d_A, d_B)` при *lower-is-better*

Наиболее консервативная функция — молекула оценивается по худшему из двух docking-скоров.
Для минимизации worst-case реализуется через `max(...)`.
Не позволяет оптимизатору «читерить», показывая отличный результат по одной мишени
и игнорируя другую. Используется как единственная reward function в primary experiment.

**Z-score нормализация:** Поскольку docking-скоры UniDock несопоставимы между таргетами (различия средних до ~2.3 kcal/mol обусловлены размером/формой кармана, см. Wang et al. 2017), в реализации RL reward используется per-target z-score: `z_X = (d_X − μ_X) / σ_X`, где `μ_X, σ_X` — среднее и стандартное отклонение docking-скоров по 1000 ZINC drug-like декоям для каждого таргета (pre-experiment калибровка, `configs/normalization.yaml`). Фактический reward: `−max(z_A, z_B)`. Это обеспечивает сопоставимость шкал и предотвращает доминирование таргета с систематически более высокими (худшими) скорами.

### Альтернативные скаляризации (sensitivity analysis only)

Следующие функции **не используются в primary experiment** — только для offline анализа чувствительности reward function. Во всех формулах `d'_A, d'_B` — shifted docking-скоры: `d'_i = d_i − min(d) + ε`, где `min(d)` берётся по всем молекулам данной пары (объединённо по всем режимам), обеспечивающие положительность для функций с ограниченной областью определения.

| Функция | Формула | Область | Свойства |
|---------|---------|---------|----------|
| **Геометрическое среднее** | `sqrt(d'_A · d'_B)` | `d' > 0` | Симметричная скаляризация, сильнее штрафует односторонние экстремумы, чем арифметическое среднее |
| **Гармоническое среднее** | `2·d'_A·d'_B / (d'_A + d'_B)` | `d' > 0` | Более чувствительно к высоким (плохим) значениям, чем арифметическое среднее; сглаживает умеренный дисбаланс |
| **Взвешенная сумма** | `w·d_A + (1−w)·d_B` | любые | Линейная скаляризация (REINVENT 4, DrugEx v3). Покрывает только выпуклый фронт Парето |
| **Взвешенное произведение** | `(d'_A)^w · (d'_B)^(1−w)` | `d' > 0` | Логарифмически линейная; при `w=0.5` эквивалентна геометрическому среднему |
| **Чебышёв** | `max(w·|d_A − z_A|, (1−w)·|d_B − z_B|)` | любые | Покрывает невыпуклые участки фронта Парето (MOEA/D, NSGA-III). `z` — утопическая точка |

### Контекст: мульти-объектная генерация в литературе

С 2024–2026 гг. наблюдается переход от скаляризации к полноценно Парето-ориентированным методам (ParetoDrug, PMMG, CMOMO, REINVENT 4 и др.), демонстрирующим улучшенное покрытие фронта Парето. В этой работе мы сознательно ограничиваемся простой worst-case скаляризацией (`max(d_A, d_B)`), чтобы **изолировать эффект double-target RL** при фиксированной архитектуре FREED++ и равном генеративном бюджете (число молекул). Подробный обзор методов — см. [Related Work](#related-work).

### Экспериментальный план по скаляризациям

1. **Primary experiment**: `max(d_A, d_B)` — единственная reward function для `double` режима.
2. **Sensitivity analysis** (offline): geometric, harmonic, weighted_sum, weighted_product, Chebyshev — пересчёт reward по уже сгенерированным молекулам. Показывает чувствительность к выбору функции, но не требует дополнительных RL-прогонов.
3. **Post-hoc Парето-анализ**: hypervolume contribution + Pareto front coverage — сравнение качества множеств решений между режимами.

## Метрики

### Определение хита и порогов

Молекула считается **хитом** по мишени X, если Boltz-2 affinity `a_X ≤ T_X`.

**Пороги `T_A, T_B`** — фиксированные, одинаковые для всех пар: `T = 0.0` (= log10(1 μM) = 1 μM).
Задаются в `configs/metrics.yaml` до начала экспериментов. Выбор 1 μM мотивирован стандартным порогом активности в HTS-кампаниях (pChEMBL ≥ 6).

**Caveat:** Boltz-2 не гарантирует глобально калиброванную шкалу IC50 по всем таргетам — модель обучена на агрегированных данных из разных assay-контекстов (Passaro et al. 2025). Поэтому:
- порог `T = 0.0` является **эмпирической, индустриально мотивированной** отсечкой, а не физически точной границей;
- таргет-специфичная калибровка Boltz-2 не проводится; все выводы по hit-rate интерпретируются как **relative comparisons between strategies** при одном и том же surrogate, а не как предсказания абсолютной активности;
- sensitivity analysis с альтернативными порогами (−1.0 = 100 nM, +1.0 = 10 μM) проверяет робастность к выбору отсечки.

### Таблица метрик

| Метрика | Определение | Назначение |
|---------|-------------|------------|
| **Dual hit-rate** (`hr_both`) | Доля молекул с `a_A ≤ T_A` И `a_B ≤ T_B` | Основной результат |
| Hit-rate A (`hr_a`) | Доля с `a_A ≤ T_A` | Per-target контроль |
| Hit-rate B (`hr_b`) | Доля с `a_B ≤ T_B` | Per-target контроль |
| Enrichment@K | `(hits_in_top_K / K) / (total_hits / N)`, top-K по `max(a_A, a_B)` ascending | Качество ранжирования |
| Иерархический bootstrap | См. ниже | Основной тест значимости |
| Cliff's delta / Cohen's d | Размер эффекта для сравнения режимов | Проверка практической значимости |

### Иерархический bootstrap

Двухуровневая процедура для корректного учёта зависимости молекул внутри одного RL-прогона:

1. **Уровень 1 (seeds)**: ресэмпл с возвращением из 5 RL-прогонов (seeds).
2. **Уровень 2 (molecules)**: внутри каждого выбранного прогона — ресэмпл с возвращением из `n_molecules` молекул.
3. Для каждого bootstrap-sample вычисляется `hr_both(double) − hr_both(single_x)`.
4. 95% CI строится по перцентилям 10 000 bootstrap-реплик; p-value — доля реплик с разностью ≤ 0.

Это предотвращает **pseudo-replication** (когда все молекулы из одного прогона считаются независимыми).

**Ограничение:** при m=5 кластерах (seeds) число уникальных комбинаций на уровне 1 невелико, что делает bootstrap CI и p-value **грубыми оценками**. Доверительные интервалы на кластерном уровне следует интерпретировать с осторожностью. Для усиления мощности: (а) основной вес доказательства несёт **effect size** (Cliff's delta), а не p-value; (б) согласованность эффекта проверяется **across core pairs** (≥3/5); (в) при наличии ресурсов число seeds может быть увеличено до 10+ в будущих экспериментах.

## Иерархия эндпоинтов и compute parity

### Primary endpoint

Сравнение dual hit-rate `hr_both` между режимами `double`, `single_a` и `single_b`
при **равном генеративном бюджете** (число сгенерированных молекул; число docking-вызовов у `double` выше — см. Compute parity):

- Каждый режим генерирует **одинаковое** число молекул (`n_molecules = 1000`) за прогон.
- Каждый режим использует **одинаковый** набор сидов (`seeds = [42, 137, 256, 512, 1024]`).
- Prior / policy init, RL-гиперпараметры, и ограничения химпространства (SA, QED, MW) идентичны.
- В `double` режиме каждый RL-шаг вызывает UniDock GPU дважды (по мишеням A и B),
  поэтому compute-cost на молекулу выше — это **сознательный trade-off**, а не артефакт.
  Альтернативный baseline с удвоенным бюджетом single-режимов рассматривается
  как sensitivity analysis, но **не является primary comparison**.

Primary metric: `hr_both(double) − hr_both(single_x)` на core-парах (заданы в `configs/pairs.yaml`).

### Secondary endpoints

| Метрика | Назначение |
|---------|------------|
| Enrichment@K (K = 10, 50, 100, 500) | Качество ранжирования: top-K молекул double vs single |
| Pareto hypervolume (HV) | Покрытие 2D-пространства `(a_A, a_B)` (см. ниже) |
| `hr_a`, `hr_b` по отдельности | Per-target деградация (см. [Критерии успеха](#критерии-успеха)) |

**Pareto hypervolume:** вычисляется по **не-доминируемому множеству** (Pareto front) из всех молекул прогона в пространстве `(a_A, a_B)`. Reference point: `r = (T_A + 2, T_B + 2)` = `(2.0, 2.0)` (log10(100 μM)) — фиксируется per-pair одинаково для всех режимов. Больший HV = лучшее покрытие. Сравнение HV между режимами (double vs single) проводится при идентичном reference point.

### Exploratory endpoints

| Метрика | Назначение |
|---------|------------|
| Tanimoto overlap с ChEMBL dual-actives | Попадание в «правильные» хемотипы (для пар с ChEMBL данными) |
| Boltz-2 `affinity_probability_binary` | Бинарный hit/non-hit для cofactor-содержащих мишеней |
| Межрежимная diversity (internal diversity) | Не коллапсирует ли double-режим в узкую область химпространства |
| Rank correlation `d_X` vs `a_X` per target | Sanity check: согласованность docking и Boltz-2 (см. ниже) |

### Ключевое допущение: docking ↔ Boltz-2 согласованность

Гипотеза проекта неявно предполагает, что оптимизация docking-скоров `d_A, d_B` (RL reward) транслируется в улучшение Boltz-2 affinity `a_A, a_B` (evaluation metric). Это **нетривиальное допущение**: UniDock (physics-based scoring function) и Boltz-2 (learned affinity) — принципиально разные аппроксимации, и их согласованность таргет-зависима.

**Sanity check (exploratory):** для каждого таргета вычисляется ранговая корреляция (Spearman ρ) между `d_X` и `a_X` на сгенерированных молекулах. Если ρ ≈ 0 на конкретном таргете, выводы по hit-rate для пар с этим таргетом интерпретируются с осторожностью.

**Линии валидации:** для усиления доверия к результатам используются два независимых скорера и дополнительный индикатор правдоподобности:
1. **UniDock docking** `d_X` — physics-based scoring (RL reward);
2. **Boltz-2 affinity** `a_X` — learned surrogate (evaluation), методически ортогональный к docking;
3. **ChEMBL Tanimoto overlap** — structural similarity к известным активам (**chemotype plausibility check**, но не независимая валидация: Boltz-2 обучен на ~750K пар из ChEMBL/BindingDB/PDBbind, поэтому высокий Tanimoto может отражать proximity к training distribution, а не истинную активность).

Согласованность двух независимых скореров (UniDock и Boltz-2) по направлению эффекта (double > single) существенно снижает вероятность того, что наблюдаемое преимущество — артефакт одного конкретного скорера. ChEMBL overlap служит дополнительной проверкой реалистичности генерируемых хемотипов.

### Compute parity — формальные гарантии

Все параметры, определяющие compute-бюджет и fairness, зафиксированы в `configs/experiment.yaml`:

```
budget.n_molecules: 1000          # одинаково для single_a, single_b, double
seeds: [42, 137, 256, 512, 1024]  # 5 прогонов × 3 режима × N пар
generator.epochs: 200             # одинаковое число RL-эпох
```

Различия между режимами ограничены **только** reward function: `−z_A`, `−z_B`, или `−max(z_A, z_B)` (z-score нормализованные docking-скоры, см. [Базовая](#базовая-baseline)).

**Primary comparison: fixed number of generated molecules.**
В `double` режиме каждый RL-шаг вызывает UniDock GPU дважды (по мишеням A и B), поэтому суммарное число docking-вызовов в `double` примерно вдвое больше, чем в `single`. Это сознательный trade-off: мы сравниваем **качество итогового набора молекул** при одинаковом числе сгенерированных SMILES, а не при одинаковом числе docking-вызовов.

**Sensitivity baseline: equal docking calls.**
Дополнительный контроль: для single-режимов увеличивается число RL-эпох (`generator.epochs: 400`) при том же `n_molecules = 1000`, что удваивает количество environment steps (и, соответственно, docking-вызовов) до уровня, сопоставимого с `double`. Это обеспечивает **равный training-time docking budget**, а не просто больше сэмплов из той же политики. Если `double` по-прежнему выигрывает при equal docking calls — эффект не объясняется только дополнительным compute.

> Увеличение `n_molecules` без удвоения RL-эпох было бы некорректным: оно лишь добавляет сэмплы из уже обученной политики, не давая ей дополнительный training signal.

## Критерии успеха

Double-target режим считается **успешным**, если выполнены **все три** условия:

1. **Превосходство по dual hit-rate**: `hr_both(double) > hr_both(single_x)` для **≥ 3 из 5 core-пар** (≥ 60%).
2. **Статистическая значимость**: для пар из п.1 — FDR-adjusted `p_value_adjusted < 0.05`, `|cliffs_delta| ≥ 0.33` (medium effect), bootstrap 95% CI не пересекает 0.
3. **Отсутствие деградации per-target**: ни на одной core-паре `hr_a(double)` или `hr_b(double)` не демонстрирует large negative effect vs соответствующего single-режима (Cliff's delta > −0.47).

Результаты фиксируются в `report/stats.json`. Критерии задаются **до начала экспериментов** (pre-registered).

## Related Work

> Этот раздел содержит подробный литературный обзор и **не входит** в обязательный набор для воспроизведения эксперимента. Для целей статьи — материал для раздела «Related Work / Background».

### Парето-оптимизация

- **ParetoDrug** (Communications Biology, 2024) — Pareto MCTS с pretrained авторегрессионной моделью. ParetoPUCT балансирует exploration и exploitation. GitHub: CNDOTA/ParetoDrug.
- **PMMG** (Advanced Science, 2025) — Pareto MCTS для 7 целей одновременно (EGFR/HER2 дуальный дизайн, QED, SA, токсичность). Доля успеха 51.65% — в 2.5x выше предыдущих SOTA.
- **CMOMO** (Briefings in Bioinformatics, 2025) — двухэтапный фреймворк глубокой многоцелевой оптимизации с динамическими ограничениями. 2x улучшение доли успеха для ингибиторов GSK3-beta.
- **EHVI** (Expected Hypervolume Improvement) — байесовский поиск на фронте Парето. Превосходит скаляризацию по покрытию фронта и сходимости при малом бюджете.

### Полифармакологическая генерация

- **POLYGON** (Nature Communications, 2024) — VAE + RL для полифармакологии. 32 синтезированных соединения на MEK1/mTOR, большинство > 50% снижение активности обоих белков.
- **Automated multi-target ligands** (Nature Communications, 2024) — химические языковые модели (CLM), pooled fine-tuning. 12 синтезированных дизайнов для 6 пар мишеней.

### GFlowNet / Synthesis-aware генерация (2025)

- **SynFlowNet** (ICLR 2025, Spotlight) — GFlowNet в пространстве реальных химических реакций. Генерирует молекулы и пути синтеза.
- **SynGFN** (Nature Computational Science, 2025) — каскад симулированных реакций, иерархическая предобученная политика.
- **RxnFlow** (ICLR 2025) — 1.2 млн строительных блоков, 71 шаблон реакций. SOTA на CrossDocked2020: средний Vina −8.85 kcal/mol.

### Boltz-2 экосистема (2025)

- **Boltz-2** (MIT/Recursion, 2025) — предсказание аффинности за 15–30 секунд вместо часов MD-симуляций. Ретроспективно превосходит всех участников CASP16 affinity challenge (Passaro et al., 2025; Boltz-2 не участвовал в соревновании — оценка проведена post-hoc на тех же данных). Корреляция Пирсона 0.66 на canonical 4-target FEP+ subset (CDK2, TYK2, JNK1, p38) из статьи, на уровне OpenFE (0.66) и ниже commercial FEP+ (0.78); на полном 8-target OpenFE benchmark — 0.62 (MIT Jameel Clinic). Независимые бенчмарки показывают более низкие значения: PL-REX (Yesylevskyy) — mean Pearson ~0.42; DeepMirror evaluation — per-target r от 0.26 (cGAS, узкий range) до 0.81 (Mpro). Boltz-2 склонен к сжатию диапазона предсказаний (~2 kcal/mol на 75/350 таргетов Uni-FEP, Chen/Rowan 2025), что усиливает таргет-зависимость перформанса и мотивирует per-target Spearman ρ sanity check в данном проекте.
- **BoltzGen** (bioRxiv, ноябрь 2025) — генеративная модель для дизайна нанободов, мини-байндеров и пептидов. Наномолярные хиты для 6/9 мишеней.
- **Boltzina** (arXiv 2508.17555, 2025) — гибрид: AutoDock Vina docking poses + Boltz-2 affinity head для ускоренного виртуального скрининга. До 11.8× быстрее Boltz-2 при сохранении превосходства над Vina/GNINA по accuracy.
- **SynFlowNet + Boltz-2** — в работе Boltz-2 (Passaro et al., 2025, Sec. 4/5.4) авторы демонстрируют связку с SynFlowNet (Cretu et al., ICLR 2025 Spotlight) — GFlowNet-генерация с Boltz-2 как scoring function в RL-петле (off-policy, replay buffer). Прямой прецедент использования Boltz-2 как surrogate scorer для RL-генерации молекул, хотя и от самих авторов модели.
- **Boltz-ABFE** (Recursion, 2025) — гибрид: Boltz-2 для скрининга + ABFE для физически обоснованной валидации.

### LLM-агенты для молекулярной оптимизации (2025–2026)

- **MultiMol** (arXiv, 2025) — двойная LLM-система: data-driven агент + литературный исследователь. Доля успеха 82.3% vs. 27.5% у предшественников.
- **M4olGen** (arXiv, январь 2026, подано на ICLR 2026) — мультиагентное прототипирование + GRPO-оптимизация. SOTA по точному контролю свойств.
- **MCCE** (arXiv, октябрь 2025) — Multi-LLM Collaborative Co-evolution. SOTA качество фронта Парето на бенчмарках.

### Multi-objective RL (обновления)

- **REINVENT 4** (J Cheminformatics, 2024) — поддерживает режимы de novo, R-group, linker, Mol2Mol; модульный скоринг. AstraZeneca, активная разработка.
- **ADMETrix** (ChemRxiv preprint 2025; accepted at ICANN 2025 Workshop on AI for Drug Discovery) — надстройка над REINVENT: 27 ADMET + 10 физ-хим свойств через ADMET AI модель. Отдельный проект (Mourdou et al.), использующий REINVENT как backend.
- **DrugEx v3** — RL + Парето-ранжирование, Tchebycheff стратегии.
- **Mol-AIR** (JCIM, 2025) — адаптивные внутренние награды для RL.

### Клиническая валидация

- **Рентосертиб** (Nature Medicine, 2025) — первый end-to-end generative-AI-discovered препарат (мишень + молекула) в Phase 2a. Мишень и молекула найдены генеративным AI (Insilico Medicine). От идентификации мишени до кандидата — 18 месяцев.
